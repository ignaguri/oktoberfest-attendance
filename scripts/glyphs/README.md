# Achievement glyph generation

The 30 achievement glyphs in `apps/mobile/assets/achievements/glyphs/` and
`apps/web/public/achievements/glyphs/` are generated by these scripts, locally,
on Apple silicon. Nothing here runs in CI and nothing here is needed to build
the apps: the exported PNGs are committed. You only need this to add a glyph or
redraw one.

## The constraint that decides everything

A badge draws its glyph at `GLYPH_SIZE_RATIO` (0.68) of its diameter, and
`SIZE_PX` is 32/40/56/96. So the real render ladder is **22 / 27 / 38 / 65 px**,
and the list views use the two smallest.

At 22px the contrast between a glyph's outline and its fill is the only variable
that decides whether you can tell what it is. Everything else (palette, detail,
shading) is invisible. Art with several separate elements, or with thin walls,
turns to mush no matter how carefully it is tuned. Judge every candidate at 22px
before anything else; `preview.sh` exists for exactly this.

## Setup

```sh
brew install imagemagick
uv tool install --force "rembg[cli,cpu]"   # the [cpu] extra is required; without
                                           # an onnxruntime backend rembg no-ops
uv tool install mflux
```

`gen.sh` pulls `filipstrand/Z-Image-Turbo-mflux-4bit` (5.9 GB) on first run. Use
the pre-quantized repo, not `Tongyi-MAI/Z-Image-Turbo`: the unquantized weights
are 31 GB of bf16 that must be quantized in RAM, which exhausts both disk and
memory on a 36 GB machine.

## Workflow

```sh
./gen.sh                      # every glyph, seed 4
./gen.sh masskrug             # one glyph
./gen.sh masskrug 1 2 3 4     # one glyph, four seeds

./sheet.sh masskrug           # every seed side by side, full size + the 22px rung
./preview.sh work/cut/masskrug-s4.png   # one glyph at all four real sizes
./diag.sh masskrug            # on white / on grey / alpha matte

./export.sh                   # resize to 256px into both apps
```

Renders land in `work/` (gitignored, ~100 MB). Existing files are skipped, so
re-running only fills gaps; delete a file or use a new seed to redraw.

`export.sh` writes 256px because the largest render is the xl hero at
96pt x 0.68 = 65pt, so a 3x screen needs 196px. 256 gives headroom at 1.4 MB per
app instead of 12.5 MB for the 1024px masters.

### chosen.tsv

`export.sh` defaults to seed 4, which won for most glyphs. `chosen.tsv` records
the per-glyph exceptions that were re-rolled later. **Add a row here when you
approve a different seed**, rather than renaming the file, or the next full
`./export.sh` will silently revert that glyph to seed 4's art.

`export.sh` and `diag.sh` both resolve it through `chosen_seed()` in
`chosen-seed.sh`, so a row moves what ships and what you inspect together.
`preview.sh` and `sheet.sh` take paths instead, since you use them to compare
seeds before one is approved.

## Adding a glyph

1. Add the id to `GLYPH_IDS` in `packages/shared/src/achievements/glyphs.ts`.
2. Add a row to `prompts.tsv`: `id <TAB> category <TAB> palette <TAB> subject`.
3. `./gen.sh <id> 1 2 3 4`, then `./sheet.sh <id>` and pick a seed.
4. Record it in `chosen.tsv` if it is not seed 4, then `./export.sh`.
5. Add a static `require()` to `apps/mobile/components/achievements/glyph-images.ts`
   in `GLYPH_IDS` order. Metro cannot resolve a computed require, so this list
   is mandatory and its test asserts the order.

## Post-processing

Re-rolling and hoping is slower than fixing an image deterministically. These
all take explicit paths, so they compose:

| Script | Use |
| --- | --- |
| `verify.py` | Report opaque-near-white % and enclosed-hole pixels per file. Run this first. |
| `alphafix.py cut` | Opaque near-white to transparent, for glass or air that should see through. |
| `alphafix.py fill` | Transparent regions *fully enclosed* by art back to opaque, for holes the matte punched by mistake. Uses a border flood fill to tell an interior hole from real outside space. |
| `rehue.py` | Shift one hue band to another with value/saturation multipliers, leaving dark outlines alone. Recolour rather than re-prompt: asking the model for a different colour changes the *shape* too. |
| `centring.py` | Measure the mark's offset from the frame centre, as a % of width/height. |
| `recentre.py` | Correct that offset. |

`verify.py` cannot tell you that a region *should* have been transparent, only
that white paint exists. A glyph that looks wrong with a clean report is
probably an alpha problem, not an art problem. Check `diag.sh`'s matte panel.

The reverse trap is the dangerous one, because it looks like success.
`preview.sh` and `sheet.sh` composite on white and the badge draws no
background fill, so a foam head that is a *hole* is indistinguishable from one
that is white paint until the glyph sits on anything else. Check a seed on a
non-white background before approving it, via `diag.sh`'s grey panel or
`magick <src> -background magenta -alpha remove -alpha off out.png`.

`verify.py`'s enclosed-hole count is the fast signal, and it swings hard
between seeds of one prompt: of four `three-glasses` seeds, one reported 19k
hole pixels and the rest 110k-131k. Only that one had painted foam, and it won
for that reason. Compare against a glyph known to be right (`masskrug` shows
magenta through the stein handle and nowhere else) rather than against zero,
since some holes are correct.

## Prompt lessons

The style preamble in `gen.sh` is doing real work; the per-glyph `subject`
column should describe shape and nothing else.

- **Dark brown outlines are the whole game.** A palette-coloured contour washes
  out at 22px. The art carries its own colours and the badge ring supplies the
  category colour, so a glyph is free to be naturally coloured (gold suns, fire
  flames) at no cost to the category system.
- **Negative prompts barely work.** "no trophy" left the trophy in twice.
  Describe the positive shape instead. Over-negating deletes the subject: asking
  for "fat wedges, not thin lines" removed a sunburst entirely.
- **Single words poison the whole image.** "a bold thick *check* mark" painted a
  checkerboard across a tent wall in all three seeds. "like a simple bar chart"
  (written to chase off a trophy) made a podium into an actual bar chart.
  "*tall* centre level" grew a spike with a star on it. "side by side" produced
  two parallel columns instead of interlocking chain links.
- **Never draw an enclosing ring.** The badge already draws one. This is in the
  shared style string because two glyphs added their own anyway.
- Keep art clear of the outer edge. `gen.sh` trims to the alpha bounding box and
  re-centres at 83% of the frame, so a generous model margin does not eat the
  badge's pixel budget.
- **The palette column carries the art's own colour, not the category's.** The
  crown was prompted `emerald green` because `full_festival` is an attendance
  achievement, which drew a green crown sitting inside a green ring and threw
  away the gold that says "top prize". The ring does the category coding, so
  repeating it in the art costs a colour and buys nothing.
- **Name the elements rather than counting them.** `drink_variety` scores
  *distinct* drink types, so its glyph has to show different vessels, and
  "two overlapping drinking vessels" quietly contradicted the metric. Naming a
  wheat glass, a stemmed wine glass and a handled stein put three in all four
  seeds. A second hue in the palette is what makes them read as different
  drinks at 22px, and it is worth bending the duotone rule for: in one hue the
  three shapes are just three containers of the same liquid.

## History

An earlier generated PNG set was replaced by hand-drawn SVG paths, which were
then replaced by this set. The vectors lost for the reason at the top of this
file: at 22px, hand-tuning bezier paths cannot buy legibility that the shape
does not have. The first *generated* set failed for a different and fixable
reason, namely low-contrast outlines and no per-glyph palette control, both of
which the current `gen.sh` addresses.

The vector set lived at `packages/shared/src/achievements/glyph-paths.ts` and
was deleted once this set shipped; `git log -- packages/shared/src/achievements/glyph-paths.ts`
still has it if a path is ever worth recovering.
